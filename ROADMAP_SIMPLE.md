## Do next — content gap found and fixed (2026-08-22)

**All 393 real words had zero morning-task passage data, live in production, since the tap-the-word-in-passage redesign shipped.** Confirmed by querying the live Supabase `word_morning_tasks` table directly: `passage` was `null` for all 393 rows. The local seed source (`zazu-words.json`) had never been updated either — every entry's `morningTask` was still on the pre-redesign schema (`taskType/sourceKind/sourceValue/correctAnswer`, no `passage` at all). Only the 3 hand-written demo fallback words (`lib/demo-alarm-words.ts`) ever had one, which is exactly why this was invisible until the Supabase env-var fix made real words start loading — before that, every session silently fell back to those 3 demo words. Root cause of *this* gap: `scripts/generate-morning-tasks.mjs` was never updated when the task type was redesigned, so it kept generating the old shape.

Fixed via a background agent: wrote and validated one natural passage per word (each containing its target word exactly once, per `isValidPassage()` in `lib/word-spotting.ts`), pushed all 393 to the live Supabase table, synced `zazu-words.json`, and patched `lib/morning-task-generator.mjs` so it now preserves an existing `passage` instead of dropping it on regeneration — verified by actually running the generator and diffing before/after. `tsc`/tests clean.

## Do next — awaiting on-device confirmation (2026-08-22 build)

A local release build with everything below was installed on-device via `expo run:android --variant release`; user testing is in progress, not yet confirmed working end to end.

- **Real Supabase data root-caused and fixed, for real this time.** Two separate bugs stacked on top of each other: (1) EAS's `preview`/`production` environments had zero `EXPO_PUBLIC_*` variables configured (only `development` did) — fixed by copying them over via `eas env:create`. (2) The deeper cause: `lib/supabase.ts`'s `readEnv()` read `process.env` via a **dynamic** bracket lookup (`env[name]`). Expo/Metro's env-var inlining only replaces **static** `process.env.EXPO_PUBLIC_X` expressions it can find via source analysis — a dynamic lookup is invisible to that pass, so on native there's no real runtime `process.env` to fall back on, and every lookup silently returned `undefined` regardless of what was configured anywhere. Confirmed via the built bundle: the literal Supabase URL was present in zero bytes of it before the fix, present after. Rewrote `getSupabaseConfig()` to use static `process.env.EXPO_PUBLIC_SUPABASE_URL` etc. member expressions directly. Web is unaffected (separate `lib/words-api.js`, not this file).
- **Fixed: deleting an alarm never cancelled its notification on the device.** `deleteAlarm` (`lib/useAlarms.ts`) removed it from the app's own list, but `syncAlarmNotifications` only touches IDs still present in the new list — the deleted alarm's daily-repeating trigger (and any pending snooze) kept firing on the phone forever, invisible to the app. Matched a symptom the user had actually seen: a notification firing for an alarm they'd deleted. Now explicitly cancels both the alarm's and its snooze's trigger IDs before persisting a deletion.
- **Fixed: coin farming via multiple alarms.** `completeWord` (`lib/useProgress.ts`) paid out the full puzzle/no-snooze/streak coin reward on every call with no same-day-repeat guard, unlike its sibling `completeDailyRitual`. Since all alarms fire the same global word-of-the-day, several alarms meant farming the same word repeatedly for free coins. Now zeroes the breakdown once `lastCompletedDate` already equals today.
- **Hold-to-snooze rebuilt** (`HoldToSnooze.tsx`) — replaces the old drag slider + full-width outline button on the alarm screen with a press-and-hold dial: `react-native-svg` gradient ring (peach→blush→lavender) that grows under the thumb while held, bounce + ripple + clock-to-checkmark draw-on when held through, haptic tick on press-start and confirm. Iterated twice on user feedback: dial grown 74→104px and hold time 1.2s→1.8s (felt too small/easy to trigger by accident), and the screen now waits 1.4s after confirming before navigating home so the animation and "Snoozing N minutes…" caption are actually visible instead of cut off. Snooze itself is now unlimited per morning (no more "Snooze used for today" hard block) — the coin bonus for not snoozing still zeroes out after the first use each day, so there's a soft cost without a wall. Screen-reader users get an `accessibilityActions` "activate" fallback since long-press gestures are unreliable with VoiceOver/TalkBack.
- **Settings' snooze duration control**, rebuilt twice more after that: fixed-list → free +/- stepper (too small a touch target, 28px) → a full-width drag slider (`SnoozeDurationSlider.tsx`) with a big serif numeral readout, the same peach→blush→lavender gradient track as the hold-to-snooze ring, and a glass-card thumb that grows while held.
- **Loading states replaced with skeletons.** New reusable `Skeleton.tsx` (pulsing placeholder blocks) swapped in for "Loading…" text + spinner across Home's word-of-day card, Learn screen, Gym screen, and Vocabulary's initial load.
- **`FloatingTabBar.tsx`** now has a real sliding active-pill indicator (`Animated.spring`, measured tab width) instead of each tab instantly swapping its own background color on press.
- **Vocabulary's missed-word coin-unlock flow** is built and code-reviewed but still not exercised on a real device — was blocked on the cloud-fallback bug above (now fixed); worth a pass once real Supabase data is confirmed loading, to actually hit a "missed day" state.

## Do next — text size audit (2026-08-22)

User pushed back hard on the morning-task screen's readability ("imagine a 70 year old using this app"), which led to a full app-wide audit rather than a one-screen fix. Counted every `fontSize` declaration in the app (shared `typography` tokens in `theme.ts` + every ad-hoc value in components): **174 total, 52% at 13px or smaller, only 9% in the 17-19px comfortable-body-reading range.** Diagnosis: not every small text is wrong — timestamps, badges, and tracked-out uppercase eyebrow labels are meant to be small and that contrast is real editorial technique per `Design.md`. The actual problem is narrower: *reading* content (definitions, hints, instructions, feature lists) was sized the same as those micro-labels.

Fixed, prioritized by traffic rather than exhaustively (174 declarations is a lot — this covers the highest-impact ones, not literally every single one):
- **Shared tokens** (`constants/theme.ts`): `wotdDef` 15→17, `wotdOrigin` 13→15, `learnDef` 17→18, `etymBody` 15→17, `mtOption` 16→17 — cascades to every screen using these.
- **Morning task screen**, finished properly this time: passage 24→28px, hint 14→16px, instruction 14→15px, candidate chip text 16→18px (with bigger padding to match), plus a flex spacer before the dismiss button so content doesn't just pin to the top with dead space below it — same layout language `AlarmScreen.tsx` already uses to centre its hero content.
- **Gold paywall**: subtitle 15→16px, feature list 14→16px.
- **Settings**: row hint text 12→14px, guest-mode description 13→15px.
- **Success screen**: coin breakdown rows 13→15px, streak banner text 13→15px, streak subtitle 11→13px, the final total row bumped further to 17px so it reads as the summary it is, not another line item.

**Not yet swept**: Vocabulary, calendar/word-detail sheets, Gym screens, onboarding — same pattern likely applies, flagged for a follow-up pass rather than done blind in this one.
